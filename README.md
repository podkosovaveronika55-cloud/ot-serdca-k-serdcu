# От сердца к сердцу

Интерактивная зимняя история: мультфильм → желание → игрушка → общая ёлка.
React + TypeScript + Vite + Tailwind CSS + Framer Motion. Собирается в статику и
работает на GitHub Pages без серверной части.

---

## Что внутри

| Экран | Что происходит |
| --- | --- |
| **Главная** | Зимний город с параллаксом, снег, мерцающие звёзды, ёлка-витрина |
| **Мультфильм** | Собственный плеер: постер, воспроизведение, громкость, полный экран, прогресс. После финальных титров появляется «Теперь очередь за тобой!» |
| **Желание** | 4 категории, текст до 180 символов, проверка на спам, режим «анонимно» |
| **Мастерская** | Форма, цвет, узор (до двух), надпись до 18 символов, вращение игрушки мышью/пальцем, масштаб, «случайная игрушка» |
| **Ёлка** | Перетаскивание игрушки на ветку (мышь и палец), подсветка свободных мест, покачивание, свечение, модалка с пожеланием, счётчик |
| **Финал** | «Посмотреть на ёлку», «Создать ещё одну игрушку», «Поделиться проектом» |

Атмосфера: снег на canvas, мерцающие звёзды, искорка за курсором, гирлянды с
загорающимися огоньками, плавные переходы между экранами.
Музыка синтезируется в браузере (Web Audio) и **никогда не включается сама** —
только по кнопке динамика в шапке.

## Демо-режим и общая база: честно о том, где хранятся игрушки

Режим определяется переменными окружения:

| Условие | Режим | Что видит посетитель |
| --- | --- | --- |
| `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` **не заданы** | `local` | Игрушки хранятся в `localStorage` **этого браузера**. На сайте написано «Демо-режим». Другие люди их не увидят. |
| Переменные заданы | `cloud` | Игрушки пишутся в Supabase и приходят всем посетителям в реальном времени. На сайте написано «Общая база». |

Имитации общей базы нет: бейдж в шапке, надпись на экране ёлки и подпись в
подвале всегда показывают фактический режим (`src/lib/store.ts` → `storeMode`).

В обоих режимах на ёлке уже висят **5 демонстрационных игрушек** — они нужны,
чтобы дерево не выглядело пустым. Они помечены `demo: true` и **не входят** в
счётчик «игрушек на ёлке».

### Как включить общую ёлку (Supabase)

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватает).
2. Откройте **SQL Editor → New query**, вставьте содержимое `supabase/schema.sql` и нажмите **Run**.
   Скрипт создаёт таблицу `toys`, политики RLS, триггер-модератор и включает realtime.
3. **Project Settings → API** — скопируйте `Project URL` и `anon public` key.
4. Локально создайте `.env.local` (образец — `.env.example`):

   ```bash
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
   ```

5. Перезапустите `npm run dev` — бейдж в шапке сменится на «Общая база».
6. Для GitHub Pages добавьте те же два значения в
   **Settings → Secrets and variables → Actions → New repository secret**
   с именами `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
   Workflow подставит их при сборке.

`anon` key публичен по замыслу — доступ ограничивают RLS-политики. **Service role
key во frontend не добавляйте никогда.**

### Защита от спама и модерация

Слой 1 — в браузере (`src/lib/moderation.ts`): длина, ссылки, телефоны и почта,
повторы символов, грубые слова, рекламные слова; не больше 6 игрушек в час с
устройства.

Слой 2 — в базе (`supabase/schema.sql`): `CHECK`-ограничения на все поля,
триггер `toys_guard()` с теми же проверками текста, политика `insert` только для
новых записей, отсутствие политик `update`/`delete`, лимит по частоте.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий `ot-serdca-k-serdcu`.
2. Загрузите содержимое папки `site/` в корень репозитория (ветка `main`).
3. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
4. Каждый `push` в `main` собирает и публикует сайт:
   `https://<логин>.github.io/ot-serdca-k-serdcu/`

Workflow сам подставляет `BASE_PATH=/<имя-репозитория>/`, поэтому ссылки на
`media/film.mp4` и стили работают из подпапки. Локально `BASE_PATH` не нужен.

### Лимит размера и Git LFS

`public/media/film.mp4` весит ~18,7 МБ (18 735 000 байт) — это **меньше лимита
GitHub в 25 МБ на файл**, поэтому Git LFS не требуется, обычный `git push`
проходит.

Если позже ролик вырастет или вы добавите версию в HD:

* либо подключите Git LFS:

  ```bash
  git lfs install
  git lfs track "public/media/*.mp4"
  git add .gitattributes public/media/film.mp4
  ```

* либо храните видео вне репозитория (Vercel/Netlify/S3) и укажите полный URL
  в `FilmScreen.tsx` вместо `${import.meta.env.BASE_URL}media/film.mp4`.

Ограничение Pages: сайт до 1 ГБ, файл до 100 МБ — при текущем размере запаса много.

## Что нужно загрузить вручную

Всё, кроме перечисленного, собирается автоматически. Руками в репозиторий нужно
положить:

| Файл / действие | Зачем |
| --- | --- |
| `public/media/film.mp4` | Готовый мультфильм (3:06). Без него плеер покажет «Видео не загрузилось» |
| `public/media/poster.jpg` | Кадр-постер: виден до нажатия Play |
| Значения `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` | Только если нужна **общая** ёлка (иначе демо-режим) |
| Запуск `supabase/schema.sql` в SQL Editor | Создать таблицу и правила доступа |
| Settings → Pages → Source: GitHub Actions | Включить публикацию |

Видео и постер уже лежат в `public/media/` — при копировании проекта достаточно
не потерять эту папку.

## Доступность и производительность

* Все интерактивные элементы — настоящие кнопки и поля с подписями и `aria-*`.
* Есть переход «К содержимому», фокус-обводки, модалка закрывается по Esc.
* `prefers-reduced-motion` отключает снег, искорку и анимации переходов.
* Снег рисуется на одном canvas с ограничением `devicePixelRatio ≤ 2`.
* Видео подключается через `preload="metadata"` — страница не тянет 18 МБ сразу.

## Про контент

Мультфильм и кадры — авторские материалы проекта. В публичном репозитории кадры
доступны всем, поэтому:

* публикуйте только те изображения, на которые есть согласие (для фото детей —
  согласие родителей);
* если нужен закрытый показ — используйте Netlify с паролем или приватный
  репозиторий с приватной сборкой.

Желания посетителей публикуются открыто и проходят модерацию; точные адреса,
телефоны и ссылки запрещены правилами.
